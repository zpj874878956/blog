# 一、项目目录

建议目录如下：

```text
helm/
├── common-chart/              # 所有微服务共用 Chart
│   ├── Chart.yaml
│   ├── values.yaml            # 默认配置
│   ├── templates/
│   │    ├── deployment.yaml
│   │    ├── service.yaml
│   │    ├── ingress.yaml
│   │    ├── hpa.yaml
│   │    ├── configmap.yaml
│   │    ├── secret.yaml
│   │    ├── serviceaccount.yaml
│   │    ├── _helpers.tpl
│   │    └── NOTES.txt
│
├── values/
│    ├── dev/
│    │     order.yaml
│    │     user.yaml
│    │     payment.yaml
│    │
│    ├── staging/
│    │     order.yaml
│    │     user.yaml
│    │
│    └── prod/
│          order.yaml
│          user.yaml
│          payment.yaml
```

这种结构最大的优点：

> **Chart 永远只有一套，30 个服务只维护 values。**

# 三、默认 values.yaml

这里放所有公共配置。

```yaml
replicaCount: 2

image:
  repository: nginx
  tag: latest
  pullPolicy: IfNotPresent

service:
  type: ClusterIP
  port: 8080

resources:
  requests:
    cpu: 200m
    memory: 512Mi

  limits:
    cpu: 500m
    memory: 1Gi

ingress:
  enabled: false

env: []

config: {}

autoscaling:
  enabled: false

nodeSelector: {}

tolerations: []

affinity: {}
```

# 四、Deployment 模板

templates/deployment.yaml

```yaml
apiVersion: apps/v1
kind: Deployment

metadata:
  name: {{ .Release.Name }}

spec:
  replicas: {{ .Values.replicaCount }}

  selector:
    matchLabels:
      app: {{ .Release.Name }}

  template:

    metadata:
      labels:
        app: {{ .Release.Name }}

    spec:

      containers:

      - name: {{ .Release.Name }}

        image: "{{ .Values.image.repository }}:{{ .Values.image.tag }}"

        imagePullPolicy: {{ .Values.image.pullPolicy }}

        ports:

        - containerPort: 8080

        resources:

{{ toYaml .Values.resources | indent 10 }}

        env:

{{- range .Values.env }}

        - name: {{ .name }}
          value: "{{ .value }}"

{{- end }}
```

这里完全没有写死。

所有内容来自：

```
.Values.xxx
```

# 五、Service 模板

```yaml
apiVersion: v1

kind: Service

metadata:
  name: {{ .Release.Name }}

spec:

  type: {{ .Values.service.type }}

  selector:

    app: {{ .Release.Name }}

  ports:

  - port: {{ .Values.service.port }}

    targetPort: 8080
```

# 六、Ingress 模板

```yaml
{{ if .Values.ingress.enabled }}

kind: Ingress

metadata:

  name: {{ .Release.Name }}

spec:

  ingressClassName: nginx

  rules:

  - host: {{ .Values.ingress.host }}

    http:

      paths:

      - path: /

        pathType: Prefix

        backend:

          service:

            name: {{ .Release.Name }}

            port:

              number: 8080

{{ end }}
```

# 十、30 个服务如何管理

例如：

```text
values/

├── dev
│     order.yaml
│     user.yaml
│     payment.yaml
│     gateway.yaml
│     auth.yaml
│     inventory.yaml
│     ...
│     共30个
│
├── staging
│     ...
│
└── prod
      ...
```

例如部署：

Order：

```bash
helm upgrade order \
./common-chart \
-f values/prod/order.yaml
```

User：

```bash
helm upgrade user \
./common-chart \
-f values/prod/user.yaml
```

Payment：

```bash
helm upgrade payment \
./common-chart \
-f values/prod/payment.yaml
```

全部都是：

```
同一个 Chart

不同 values
```

# 十一、CI/CD 如何自动更新镜像

GitLab CI 构建完成后：

```yaml
build
↓

推送 Harbor

↓

生成镜像：

order:v1.3.8

↓

修改

values/prod/order.yaml

image:
  tag: v1.3.8

↓

git commit

↓

ArgoCD 自动同步

↓

Kubernetes RollingUpdate
```

例如：

```yaml
image:

  repository: harbor.company.com/prod/order

  tag: v3.1.9
```

整个部署过程无需修改 Deployment YAML。

# 十二、企业级最佳实践

如果是互联网公司（美团、滴滴、腾讯、字节等）的生产环境，我建议进一步采用 **Helm + GitOps** 的目录组织，将应用模板与环境配置彻底分离：

```text
gitops/
├── helm-chart/                  # 唯一公共 Chart
│   ├── templates/
│   ├── Chart.yaml
│   └── values.yaml
│
├── environments/
│   ├── dev/
│   │   ├── order.yaml
│   │   ├── user.yaml
│   │   └── ...
│   ├── staging/
│   └── prod/
│       ├── order.yaml
│       ├── user.yaml
│       └── ...
│
├── applications/                # ArgoCD Application 定义
│   ├── dev/
│   ├── staging/
│   └── prod/
│
└── .gitlab-ci.yml
```
